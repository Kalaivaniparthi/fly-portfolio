Build Write-Up — AI Book Tracker

Stack chosen and why

  • FastAPI — fastest way to build production-grade Python APIs with auto-generated docs.
  • PostgreSQL in Docker — production-grade relational DB; Docker means it runs identically everywhere.
  • Supabase — outsourcing auth to a specialist rather than rolling my own password system.
  • Groq AI — free, fast, no credit card required.

The hardest thing that broke

Mid-build, Groq deprecated the Llama model I was using. Every AI call returned model_not_found and I lost an hour confused. The fix: I ran client.models.list() to see what was actually available, switched to qwen/qwen3.8-27b, and added /no_think to the system prompt to prevent empty outputs from reasoning models.

What I'd build next

A minimal React frontend that consumes this API, deployed on Vercel. Then swap the scraper to monitor price changes on a schedule using a cron job.

Plan to keep building

Next piece: React frontend for Book Tracker — a public "browse books" page and a logged-in "my list" page. Real reminder: I've set a calendar event for October 15 to start it.
