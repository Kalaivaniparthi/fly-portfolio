Book Tracker API

Problem: I wanted to build a multi-user app that combines auth, AI, and a real database.

What I did: Built a FastAPI + PostgreSQL + Docker API. Scraped 60 books, generated AI summaries with Groq, and let users save books to private reading lists using Supabase JWTs.

What came of it: A working API where User A can never see User B's data. All endpoints tested in Swagger with real JWT auth.

Auth API with Supabase

Problem: I needed to understand how modern auth works — JWTs, protected routes, no hand-rolled password systems.

What I did: Built a FastAPI service using Supabase as the identity provider. Added signup, login, logout, and protected routes with a reusable auth dependency.

What came of it: A working API with padlock-protected endpoints in Swagger. Tampered tokens get rejected with 401.

CRUD API in Docker with PostgreSQL

Problem: Wanted to prove I could build something that survives restarts.

What I did: Built a FastAPI CRUD API, then swapped in-memory storage for PostgreSQL running in Docker. Kept the routes identical — only the storage layer changed.

What came of it: Proved persistence: created data, stopped all containers, restarted, data was still there.
